Dydra API

Glossary

The terms below name the request properties which govern query processing. Each is set in one or more of five places – the request protocol (a URL argument or an HTTP header), the request text (a SPARQL declaration), or the repository, account and system configuration. The values combine as described in HTTP Request Parameters: a request value supercedes the query text, which supercedes configuration, and among configuration values repository supercedes account, which supercedes system. No more specific setting may raise a limit beyond that of a more general one.

API key

A token which authenticates the requesting agent in place of a user name and password. Presented in the request URL or an HTTP header as authentication-key or api-key (string). Token authentication is one of the identification methods described in Entity Identification.

base iri

The IRI against which relative IRIs in the query text are resolved. Set with base-iri (iri) in the request URL, with the BASE declaration in the query text, or in the system configuration. Any initial base iri expands qname terms as the query text is parsed, so it is compiled into a cached query and a subsequent request cannot change it.

content type

The media type of the response document, requested with the accept or response-content-type HTTP header. The response headers which report the type and the encoding of a result are described in Sparql Response.

dataset

The graphs against which a query is evaluated. Named and default graphs are specified in the request URL with named-graphs, named-graph-uri, default-graphs and default-graph-iri (iri list), or in the query text with FROM, FROM NAMED, WITH and WITH NAMED. Two further terms fix what the unqualified references denote:

  • default-context-term (urn) : <urn:dydra:all>, <urn:dydra:default>, <urn:dydra:named>

  • named-contexts-term (urn) : <urn:dydra:all>, <urn:dydra:default>, <urn:dydra:named>

Where a query is cached and a dataset was specified, the respective complement may still be changed on re-execution.

describe form

The rule by which a DESCRIBE query expands a term into statements. describe-form (urn) selects the form, either <urn:dydra:simple-concise-bounded-description> or <urn:dydra:simple-symmetric-concise-bounded-description>; describe-subject-depth and describe-object-depth (integer) bound the depth to which a term serves to match statement subjects and objects; describe-properties (<urn:dydra:true> / <urn:dydra:false>) extends a standard concise bounded description to statements which share terms other than blank nodes. See Describe Form in HTTP Request Parameters.

dynamic binding

A value bound to a query variable for the duration of one execution – a binding with indefinite scope and dynamic extent. Written in the request URL as $variable=value. View parameters establish dynamic bindings in the same way; see View Requests.

entailment

The ruleset in effect when a basic graph pattern is interpreted, given as entailment-ruleset or ruleset (iri list) in the request URL, as a declaration in the query text, or in the repository, account or system configuration. Applicable rules are compiled into the bgp interpretation, so a cached query retains the ruleset which was in effect when it was compiled.

federation

Whether, and how, a query may draw on a repository other than its own. federation or federation-mode (urn) selects the mode: <urn:dydra:internal> – the sub-query is executed as a subtask in the same processor; <urn:dydra:external> – the sub-query is requested of a remote SPARQL endpoint; <urn:dydra:none>. Access in either direction must be authorized: authorized-client-locations and authorized-service-locations (iri, repository configuration only) record, as ACL entries, the originating repositories and request agents which a reference is permitted to come from. See Federation.

index

An auxiliary index maintained for a repository and used by the query planner in place of a scan. property-index (list string iri) declares the indexed properties in the repository, account or system configuration; an index cannot be set by a request. Free text indices are created on demand when a query addresses them, and are refreshed by deletion; see Index Management.

processing bounds

The resources one query execution may consume: memory-limit, solution-limit and time-limit (also timeout), all integers. Settable in the request URL, in the query text and in all three configurations, subject to the rule that a more specific setting may only lower a bound. Provisioning of resources by identity and class is a separate matter, described in Quality of Service Provisioning.

provenance information

The record of how a repository state came to be – data lineage, retrospective state, and responsibility for changes. provenance-repository-id (string) names the repository in which the records for an update request are saved. Lineage is first-order, at the level of graphs rather than individual statements. See Provenance.

query text

The SPARQL query itself, carried as the query (string) argument of the request URL or as an argument in a request form. See Query Text in HTTP Request Parameters.

repository

The store a request applies to, and the unit which carries revisions, configuration and access control. Identified in the request URL by repository-id (string), and a particular state of it by revision-uuid (string). Its term and statement statistics affect pattern suppression, reordering and solution propagation, and are therefore compiled into a cached query. Administration of the resource is described in Repository Management.

response bounds

The extent of the solution sequence returned: limit or response-limit, and offset or response-offset (integer). Settable in the request URL, in the query text and in all three configurations. As with any limit, a more specific setting may only lower the value.

revision

A committed state of a repository, identified by the type 1 UUID of the transaction which created it – so the identifier carries both the host on which the transaction originated and a time sequence value. Given in a request as revision-uuid (string). A request without one applies to the latest revision. See Revision Designator Specification and Repository Revision Metadata.

revision-windows

A temporal bound on the revisions a repetitive result is drawn from, supplied as the revision-window (string) HTTP header. Applies to streaming requests over MQTT. See Revision Window Specification and Revision Window Syntax in HTTP Request Parameters.

skolemization mode

How blank nodes are replaced by IRIs. skolemize (urn) selects the mode: <urn:dydra:skolemize>, <urn:dydra:skolemize-export> or <urn:dydra:skolemize-import>; skolemize-prefix (string) supplies the prefix for the generated IRIs. Settable in the request URL, in the query text and in all three configurations.

undefined variable

What the processor does with a variable which the query text never binds. undefined-variable-behavior (urn) selects the behaviour: <urn:dydra:error>, <urn:dydra:dynamic-binding> – the variable is taken to be a dynamic binding supplied by the request – or <urn:dydra:warning>. The mode determines the mechanism generated to interpret free variable references and is therefore compiled into a cached query.

user query id

An identifier the client assigns to a request so that it can be correlated with the response and with service records. Presented as the Client-Request-ID HTTP header, or in the request URL as user-id or user_id (string). A request which carries one has it returned in the response Client-Request-ID header; see Sparql Response.

values clauses

Replacement text for the VALUES clauses of the query, supplied as the values (string) argument in the request URL or in a request form. The argument syntax follows the datablock production of the SPARQL query syntax, and an argument is matched to a clause by that clause’s projection variables. See Values Clauses in HTTP Request Parameters.

xslt

A style sheet to be applied to the response document, given as xslt (iri) in the request URL or in an HTTP header.

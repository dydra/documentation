Abstract Algebra Expressions

Dydra accepts query requests in the form of abstract algebra expressions in addition to SPARQL texts. These express each operation as an s-expression, in which the operator is present in the first position and any arguments occupy successive positions.

In the case of a simple query such as

SELECT ?s ?p ?o WHERE { ?s ?p ?o }

the equivalent algebra expression would be

(select
   (bgp
     (triple ?:s ?:p ?:o))
   (?:s ?:p ?:o))

SPOCQ SPARQL Algebra Operators — spocq.a package reference

This document catalogs every macro exported from the org.datagraph.spocq.algebra (nicknamed spocq.a) package, plus a handful of supporting functions accessed from algebra expressions. The macros constitute the symbolic SPARQL expression (SSE) algebra that the SPARQL parser emits and the query compiler consumes; each macro corresponds to one SSE form and one or more SPARQL grammar productions.

Per-entry headings carry the macro’s external name (the bar-quoted symbol-name) and its lambda list. The line under each heading marks the entry as MACRO or FUNCTION and, for the predicate / value operators, gives a prose pseudo-type-signature in the SPARQL/XPath operator-mapping notation:

( ( arg-type ... ) return-type )

Where two spellings exist — a SPARQL-spec strict case (e.g. isBlank) plus a lower-case alias (isblank) — both are listed alongside.

SPARQL 1.2 additions are grouped together at the end of each affected category (triple-term constructor / accessors / predicate, language direction).

02
xpath / xsd

XPath / XSD date-component functions

These are functions (not macros) accessed from the algebra; they correspond to fn:*-from-dateTime and apply to xsd:date / xsd:dateTime / xsd:duration / xsd:gYear / … values.

FUNCTION ( (or DATE DATE-TIME DAY-TIME-DURATION G-DAY G-MONTH-DAY) ) T

The function DAY returns the day part of arg as an integer. Corresponds to fn:day-from-dateTime and its variations.

FUNCTION ( (or DATE-TIME DAY-TIME-DURATION TIME) ) T

The function HOURS returns the hours part of arg as an integer. The value is as given in the lexical form of the XSD dateTime. Corresponds to fn:hours-from-dateTime.

FUNCTION ( (or DATE-TIME DAY-TIME-DURATION TIME) ) T

The function MINUTES returns the minutes part of the lexical form of arg. Corresponds to fn:minutes-from-dateTime.

FUNCTION ( (or DATE DATE-TIME YEAR-MONTH-DURATION G-MONTH G-MONTH-DAY G-YEAR-MONTH) ) T

The function MONTH returns the month part of arg as an integer. Corresponds to fn:month-from-dateTime.

FUNCTION ( ( DATE-TIME DAY-TIME-DURATION TIME ) T )

The function SECONDS returns the seconds part of the lexical form of arg. Corresponds to fn:seconds-from-datetime.

FUNCTION ( ( xsd:dateTime ) simpleLiteral )

The function TZ returns the timezone part of arg as an xsd:dayTimeDuration. Raises an error if there is no timezone. Corresponds to fn:timezone-from-dateTime except for the treatment of literals with no timezone. As all times are recorded as Zulu, the function constantly returns 'Z'.

FUNCTION ( (or DATE DATE-TIME YEAR-MONTH-DURATION G-YEAR G-YEAR-MONTH) ) T

The function YEAR returns the year part of arg as an integer. Corresponds to fn:year-from-dateTime.

Statement markers (used inside bgp body)

These macros never appear at the top of an algebra form; they tag the constituent triple / quad patterns inside a bgp.

MACRO

The asserted-triple statement marker used inside a bgp body to denote an (S P O) match. Trailing REST captures SPARQL 1.2 reifier / annotation keyword tails: :reifier r (produces a reified statement carrying the reifier identity) and :annotation records (produces additional asserted triples on the reifier).

MACRO

The asserted-quad statement marker used inside a bgp body to denote an explicitly- graphed match (S P O G).

MACRO

Construct a literal list value within the algebra. Used by the parser to carry SPARQL property-path / IN argument sequences as constant data.

04
solution-field

Solution-field producers

Forms that introduce a solution field, either from the dataset (bgp) or from a constant / external source (bindings, csv-bindings, json-bindings, table, null). ask reduces a solution field to a single boolean.

MACRO ( ( solutionField ) xsd:boolean )

The ASK form yields true iff the solution field is not empty. No information is returned about the possible query solutions, just whether or not a solution exists.

MACRO

Basic graph pattern. BODY is a list of statements (triple, quad, or nested algebra forms such as graph, filter, optional, union, etc.) that collectively constrain the dataset to a single solution stream. The macro lowers BODY through a fixed sequence of pattern-rewrite phases — statement combination, filter pushdown, sip-source promotion, service-join expansion, and so on — and finishes with the storage layer’s match-field operators.

MACRO ( ( solutionSequence variable* ) solutionField )

A BINDINGS form combines a sequence of solutions with variables as dimensions to produce an unordered solution field, which can serve as an argument to other query forms. The solution sequence may comprise constant values only. This implements the SPARQL VALUES expression.

MACRO

Construct a bindings-style solution field from a CSV document SOURCE (string or pathname). When VARIABLES is supplied, the result is projected to those columns by name; otherwise all columns named in the CSV header become dimensions.

MACRO

Construct a bindings-style solution field from a SPARQL Results JSON document SOURCE (string or pathname). When VARIABLES is supplied, the result is projected to those columns by name; otherwise the result’s head vars list becomes the dimensions.

MACRO ( ( variable*? ) solutionField )

A NULL form produces an empty solution field of the given dimensionality.

MACRO ( ( variable*? ) solutionField )

A TABLE form produces a zero-dimension solution field with a single solution. If in the scope of a graph form, a constant graph name will reduce the result to a null field if the graph does not exist.

Per rec-sparql [1], the ‘unit’ table is “one solution that does not bind any variables.”

[1] http://www.w3.org/TR/rdf-sparql-query/#emptyGroupPattern

05
solution-field

Solution-field combinators

Two-field operators producing a third field by some combination rule.

MACRO ( ( solutionField solutionField ) solutionField )

A DIFF form combines two solution fields with an optional predicate to be applied to each compatible, merged solution. The result is those solutions from the first field which are either incompatible with all solutions in the second field, or fail the predicate when combined with compatible solutions.

MACRO ( ( solutionField solutionField (function (solution) xsd:boolean)? ) solutionField )

A JOIN form combines two solution fields and yields a new field in which each solution is either a merge of two compatible solutions from the constituent fields, in the case where a natural join is possible, or an element of the cross join of the two fields, in the case where no dimension agrees. Where a test predicate is given, all result solutions satisfy it.

MACRO ( ( solutionField solutionField (function (solution) xsd:boolean)? ) solutionField )

A LEFTJOIN form combines two solution fields and yields a new field in which each solution is either a merge of two compatible solutions from the constituent fields, or a solution from the first field, in the case where a natural join is possible, or an element of the cross join of the two fields, in the case where no dimension agrees. Where a test predicate is given, all result solutions satisfy it.

MACRO

Internal variant of leftjoin whose first argument is already in evaluated form (used by the compiler’s lowering passes for nested OPTIONAL).

MACRO ( ( solutionField solutionField ) solutionField )

A MINUS form combines two solution fields to produce a result field which contains all solutions from the first field for which no compatible solution is present in the second field.

MACRO ( ( solutionField solutionField ) solutionField )

A UNION form combines two solution fields to produce a result field which contains all solutions from the first field followed by those in the second.

06
solution-field

Solution-field transformers

Single-field operators producing a transformed field by extending, filtering, projecting, ordering, or slicing the input.

MACRO ( ( solutionField ) solutionField )

A DISTINCT form accepts a single solution field and yields an analogous field which removes duplicate solutions.

MACRO

Wrap a sequence of FILTER-clause expressions; equivalent to their conjunction under &&. Used by the parser when a FILTER clause produces multiple sub-expressions.

MACRO ( ( solutionField variable RDFTerm ) solutionField )

An EXTEND form extends each solution in its solution-field argument with an additional dimension in which the given variable is bound to the respective result of evaluating the given expression for each solution. If the evaluation fails, the variable remains unbound.

MACRO

Variant of extend whose tail ARGS may contain further (variable expression) bindings which the parser emits when several BIND clauses appear in sequence; the expansion rewrites them into nested extend forms, evaluated left-to-right.

MACRO ( ( solutionField (function (solution) xsd:boolean) ) solutionField )

A FILTER form applies a predicate function to each solution in a given field to generate a new solution field which includes only those input solutions which satisfy the predicate.

Where possible, the evaluation process folds any constant values into the argument patterns and pushes the predicate to limit the matching and combination processing in the constituent solution field.

MACRO ( ( solutionField (function (solution solution) xsd:boolean) ) solutionField )

An ORDER form applies an ordering predicate to a given solution field to produce a result field in which each successive solution pair satisfies the given predicate.

MACRO ( ( solutionField ) solutionField )

A PROJECT form produces a new solution field in which each solution comprises just the specified elements. Each element can be either a variable, or a (variable expression) binding. In the first case, any supplied argument value is included in the result solution. In the second, the respective expression is evaluated for each solution to produce the respective result. If the variable is not bound in the original solution, no value appears in the result.

MACRO ( ( solutionField ) solutionField )

A REDUCED form accepts a single solution field and yields an analogous field which removes the duplicate solutions. Unlike distinct, an implementation is permitted to retain or remove duplicates (best-effort).

MACRO ( ( solutionField ) solutionField )

A SLICE form reduces a given solution field to produce a result field which includes only those solutions within the specified [offset end) interval.

07
aggregation

Aggregation

MACRO

Compute the aggregations specified by BINDINGS over the input SOLUTION-FIELD grouped on KEY-BINDINGS. Each BINDING is a (variable aggregate-form) pair; each KEY-BINDING is a (variable expression) pair as in group. The remaining keys (COUNT / END / LIMIT / OFFSET / START) govern slicing applied to the resulting aggregated rows.

MACRO ( ( solutionField ( variable (function (solution) RDFTerm) )* ) ( RDFTerm solutionField )* )

A GROUP form extends a given solution field with keys composed of a set of computed bindings and then segments the field according to those keys. Each KEY-BINDING is a (variable expression) pair; the expression is evaluated for each input solution to compute the variable’s value, and those variables become the partitioning keys.

MACRO

Determine the aggregation variant and expand accordingly. segment is the algebra form that the parser emits for a SELECT with GROUP BY / aggregation expressions; the macroexpansion routes to the most efficient of aggregate, project, or group-and-fold for the specific request. MODIFIERS captures the SOLUTION MODIFIER clauses (HAVING / ORDER BY / LIMIT / OFFSET) that must be applied around the aggregation result.

08
graph scope

Graph scope

MACRO ( ( (or anyURI variable) graphPattern ) solutionField )

A GRAPH form modifies the application of a basic group graph pattern to either:

  • constrain its extent to the specific graph named by the constant IRI, or

  • limit its domain to those named graphs enumerated in the dataset definition, or

  • permit it to range over all named graphs.

In the latter two cases, the result solution field will include a binding for the respective graph in each solution.

dependent join (sparql

Dependent join (SPARQL 1.2 LATERAL)

MACRO

Employ the first solution field to establish the dynamic evaluation environment for the second field. Implements the SPARQL 1.2 LATERAL semantics (one-sided correlated join) reducing to join.

MACRO

Like dependent but reduces to leftjoin for the OPTIONAL-style variant; solutions in the first field are preserved when the second yields nothing.

top-level query forms

Top-level query forms

MACRO ( ( solutionField pattern ) RDFSolutionField )

A CONSTRUCT form applies the given graph-pattern template to each solution of the given solution-field to produce a field which denotes the projected RDF graph.

MACRO ( ( solutionField anyURI* ) RDFSolutionField )

A DESCRIBE form merges all resource IRIs from the given solution-field and subject resource list, performs iterative queries to produce the bounded descriptions for those resources, and yields an RDF graph which enumerates their relations in the store.

The extent is governed by configuration parameters:

  • <urn:dydra:describeForm>

  • <urn:dydra:describeSubjectDepth>

  • <urn:dydra:describeObjectDepth>

MACRO

Top-level SELECT form. EXPRESSION is the WHERE-clause’s algebra; SELECTION-SPECIFICATION is the projection list — variable names, or (variable expression) bindings, possibly preceded by the modifier keywords :distinct, :reduced, :group-by, :having, :order-by — and the remaining keys describe pagination.

MACRO

MACRO

Delete a constant set of triples / quads. Companion to insertData; the argument is intended to be a constant data form, validated at macroexpansion time.

MACRO

Given a list of quad patterns, use them both to match against the store and to construct the statements to be deleted.

MACRO

Drop a graph: delete its content and remove its name from the dataset. GRAPH may be an IRI or one of :default, :all, :named.

MACRO

Insert a constant set of triples / quads. Companion to deleteData; the argument is intended to be a constant data form, validated at macroexpansion time.

MACRO

MACRO

SPARQL update DELETE / INSERT / WHERE / WITH compound form.

MACRO

MACRO

Top-level wrapper for one or more update OPERATIONS (each one of insertData, deleteData, modify, load, clear, drop, create, add, copy, move, or conditional). Operations execute in sequence within the surrounding transaction.

Remote query

MACRO

Perform a remote SPARQL query against the endpoint at IRI and return the result field. :silent t suppresses endpoint errors; :query-text "..." overrides the serialised sub-query text.

MACRO

Perform a remote query and natural-join it with SIP-SOURCE. The base field is SIP-SOURCE (sideways-information-passing source); compiles into a single round-trip per chunk of the sip-source.

revision / spocq

Revision / spocq temporal extension

MACRO

spocq temporal extension: perform the sub-query at the given revision and return the result field. REVISION-DESIGNATOR is a revision IRI, a relative offset (e.g. -1), or a literal datetime; GROUP-GRAPH-PATTERN is the algebra form to evaluate against the resolved revision.

MACRO

spocq temporal extension. Return the dateTime associated with the currently-active revision of *repository* — i.e. the moment a revision sub-query is evaluated ‘as of’. Useful in WHERE clauses that need to reason about revision time independently of now.

MACRO ( () xsd:dateTime )

The function NOW returns an XSD dateTime value for the current query execution. All calls to this function in any one query execution must return the same value. The moment is that recorded when the query process was created.

MACRO ( ( xsd:dateTime ) xsd:dayTimeDuration )

The function TIMEZONE returns the timezone part of arg as an xsd:dayTimeDuration. Raises an error if there is no timezone. This function corresponds to fn:timezone-from-dateTime except for the treatment of literals with no timezone.

As all values are represented as Zulu times, the function constantly returns 'PT0S'^^xsd:dayTimeDuration.

arithmetic

Arithmetic

MACRO ( ( numeric numeric? ) numeric )

MACRO ( ( numeric numeric? ) numeric )

MACRO ( ( numeric numeric ) numeric )

MACRO ( ( numeric numeric ) numeric )

MACRO ( ( numeric ) numeric )

The function ABS returns the absolute value of arg. An error is raised if arg is not a numeric value. This function is the same as fn:numeric-abs for terms with a datatype from XDM.

MACRO ( ( numeric ) numeric )

The function CEIL returns the smallest (closest to negative infinity) number with no fractional part that is not less than the value of arg. Errors on non-numeric. Equivalent to fn:numeric-ceil for terms with a datatype from XDM.

MACRO ( ( numeric ) numeric )

The function FLOOR returns the largest (closest to positive infinity) number with no fractional part that is not greater than the value of arg. Errors on non-numeric. Equivalent to fn:numeric-floor for terms with a datatype from XDM.

MACRO ( ( numeric ) numeric )

The function ROUND returns the number with no fractional part that is closest to the argument. If there are two such numbers, the one that is closest to positive infinity is returned. Errors on non-numeric. Equivalent to fn:numeric-round for terms with a datatype from XDM.

MACRO ( ( numeric numeric ) numeric )

Two-argument maximum (the operator-mapping form). Aggregate MAX is built from aggregate.

MACRO ( ( numeric numeric ) numeric )

Two-argument minimum (the operator-mapping form). Aggregate MIN is built from aggregate.

MACRO ( () xsd:double )

The function RAND returns a pseudo-random number between 0 (inclusive) and 1.0e0 (exclusive). Different numbers can be produced every time this function is invoked. Numbers should be produced with approximately equal probability.

15
predicates

Predicates

Operators that yield xsd:boolean, designed to be composed inside FILTER and IF tests. The three sub-categories — comparison, boolean / logical, and type predicates — together cover all the SPARQL value predicates.

MACRO ( xsd:boolean )

The = operator returns TRUE if term1 and term2 are the same RDF term as defined in Resource Description Framework (RDF): Concepts and Abstract Syntax [CONCEPTS]; produces a type error if the arguments are both literal but are not the same RDF term; returns FALSE otherwise. term1 and term2 are the same if any of the following is true:

  • term1 and term2 are equivalent IRIs as defined in 6.4 RDF URI References of [CONCEPTS].

  • term1 and term2 are equivalent literals as defined in 6.5.1 Literal Equality of [CONCEPTS].

  • term1 and term2 are the same blank node as described in 6.6 Blank Nodes of [CONCEPTS].

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

Inequality predicate. Returns the boolean negation of = over the same domain.

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

The function < compares the two arguments and returns true iff arg1 is strictly less than arg2. Where it can be determined that both arguments are constants — in particular, strings with language tags — delegate to the store’s collation-sequence- dependent ordering operator. In other cases, retrieve the terms and continue with those values as arguments.

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

The function <= compares the two arguments and returns true iff arg1 is less than or equal to arg2. Same dispatch as <.

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

MACRO ( ( rdfTerm rdfTerm ) xsd:boolean )

The function SAMETERM returns TRUE if term1 and term2 are the same RDF term as defined in [CONCEPTS]; returns FALSE otherwise. Differs from = in that it never raises a type error and never folds value-equivalent literals of distinct datatypes.

MACRO ( xsd:boolean )

The && operator returns a logical AND of left and right. Note that logical-and operates on the effective boolean value of its arguments.

XQuery defines that an IF form need not evaluate an unselected alternative. It says nothing about the semantics for logical operators. This implementation handles the two expressions the same.

With respect to errors: a logical-and that encounters an error on only one branch returns an error if the other branch is TRUE, and FALSE if the other branch is FALSE. A logical-or / logical-and that encounters errors on both branches will produce either of the errors.

MACRO ( xsd:boolean )

The || operator returns a logical OR of left and right. Same EBV / error rules as &&.

MACRO ( xsd:boolean )

Logical negation; returns the boolean negation of EXPRESSION’s effective boolean value.

MACRO ( rdfTerm )

The COALESCE function returns the value of the first expression which evaluates without an error. In SPARQL, evaluating an unbound variable raises an error. If none of the arguments evaluates to an RDF term, an error is raised. If no expressions are evaluated without error, an error is raised.

When an expression is a variable, the macro prefaces evaluation with a test for unbound to skip error handling.

MACRO ( ( graphPattern ) xsd:boolean )

The filter operator EXISTS takes a graph pattern and returns true / false depending on whether the pattern matches the dataset given the bindings in the current group graph pattern, the dataset and the active graph at this point in the query evaluation. No additional binding of variables occurs. Although it accepts a graph pattern rather than a value expression, the result is an xsd:boolean and EXISTS appears only in positions that consume one — chiefly FILTER and IF tests.

NOT EXISTS translates into fn:not(EXISTS{...}).

MACRO ( rdfTerm )

The IF form evaluates the first argument, interprets it as an effective boolean value, then returns the value of consequent if the EBV is true, otherwise it returns the value of alternative. Only one of consequent and alternative is evaluated.

If evaluating the predicate expression raises an error, then an error is raised for the evaluation of the IF expression.

MACRO ( ( rdfTerm . rdfTerm* ) xsd:boolean )

The IN operator tests whether the RDF term on the left-hand side is found in the values of the list of expressions on the right-hand side. The test is done with the = operator.

A list of zero terms on the right-hand side is legal (with result false). Errors in comparisons cause the IN expression to raise an error if the RDF term being tested is not found elsewhere in the list of terms.

The IN operator is equivalent to the SPARQL expression (lhs = expression1) || (lhs = expression2) || ....

NOT IN (...) is equivalent to !(IN (...)).

MACRO ( ( rdfTerm . rdfTerm* ) xsd:boolean )

NOT IN (...) is equivalent to !(IN (...)).

MACRO ( ( RDFTerm ) xsd:boolean )

The function BOUND returns true if var is bound to a value. Returns false otherwise. Variables with the value NaN or INF are considered bound. If there is no lexical definition, the result is constantly false.

MACRO ( ( RDFTerm ) xsd:boolean )

Returns true if expression yields a blank node. Returns false otherwise. Lowercase alias: isblank.

MACRO ( ( RDFTerm ) xsd:boolean )

Returns true if term is an IRI. Returns false otherwise. Lowercase alias: isiri.

MACRO ( ( RDFTerm ) xsd:boolean )

Returns true if expression yields a literal. Returns false otherwise. Lowercase alias: isliteral.

MACRO ( ( RDFTerm ) xsd:boolean )

Returns true if term is a numeric value. Returns false otherwise. term is numeric if it has an appropriate datatype (see the section “Operand Data Types”) and has a valid lexical form, making it a valid argument to functions and operators taking numeric arguments. Lowercase alias: isnumeric.

MACRO ( ( RDFTerm ) xsd:boolean )

isURI is an alternate spelling for the isIRI operator. Lowercase alias: isuri.

MACRO ( ( RDFTerm ) xsd:boolean )

The isTriple function returns true iff the argument is an RDF triple term, otherwise false. SPARQL 1.2.

MACRO ( xsd:boolean )

Return true iff the type of the given term is the given type. Where constants are involved, implement as a term-number comparison for the IRI and the term type.

16
term constructors

Term constructors

MACRO ( ( literal? ) blankNode )

The BNODE function constructs a blank node that is distinct from all blank nodes in the dataset being queried and distinct from all blank nodes created by calls to this constructor for other query solutions.

If the no-argument form is used, every call results in a distinct blank node. If the form with a simple literal is used, every call results in distinct blank nodes for different simple literals, and the same blank node for calls with the same simple literal within expressions for one solution mapping.

MACRO ( ( RDFTerm ) iri )

The IRI function constructs an IRI by resolving the string argument (see RFC 3986 and RFC 3987 or any later RFC that supersedes them). The IRI is resolved against the base IRI of the query and must result in an absolute IRI.

The URI function is a synonym for IRI. If the function is passed an IRI, it returns the IRI unchanged. Passing any RDF term other than a simple literal, xsd:string, or an IRI is an error. An implementation may normalize the IRI.

MACRO ( ( RDFTerm ) iri )

Synonym for iri.

MACRO ( ( simpleLiteral IRI ) literal )

The STRDT function constructs a literal with lexical form and type as specified by the arguments.

MACRO ( ( simpleLiteral simpleLiteral ) literal )

The STRLANG function constructs a literal with lexical form and language tag as specified by the arguments.

MACRO ( ( xsd:string xsd:string xsd:string ) plainLiteral )

Construct a plain literal whose stored language string is the concatenation lang--dir of the lang and dir arguments. SPARQL 1.2.

MACRO ( () simpleLiteral )

Return a string that is the scheme-specific part of a UUID — the result of generating a UUID, converting to a simple literal and removing the initial urn:uuid:.

MACRO ( () iri )

The UUID function returns a fresh IRI from the UUID URN scheme. Each call of UUID() returns a different UUID.

MACRO ( ( RDFTerm RDFTerm RDFTerm ) triple-term )

The TRIPLE function constructs a triple-term value from three RDF terms. Constructing a triple-term where any argument is unbound is an error.

The PascalCase name distinguishes the value-form expression from the lowercase triple statement marker used inside a bgp body. SPARQL 1.2.

datatype

Datatype

MACRO ( ( literal ) iri )

Returns the datatype IRI of a literal:

  • If the literal is a typed literal, return the datatype IRI.

19
language

Language

MACRO ( ( literal ) simpleLiteral )

Returns the language tag of literal, if it has one. Returns "" if the literal has no language tag. Note that the RDF data model does not include literals with an empty language tag.

MACRO ( ( simpleLiteral simpleLiteral ) xsd:boolean )

The function LANGMATCHES returns true if language-tag (first argument) matches language-range (second argument) per the basic filtering scheme defined in [RFC4647] section 3.3.1. language-range is a basic language range per Matching of Language Tags [RFC4647] section 2.1. The CONCAT function corresponds to the XPath fn:concat function. The function accepts string literals as arguments.
